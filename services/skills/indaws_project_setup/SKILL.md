# Indaws Project Setup v2.2

Bootstraps Odoo project directories with the right context so every other skill works correctly from the start.

After running this skill, the project has a CLAUDE.md with the Odoo version, relevant skills for the user's role, and (for developers) local source code cloned/updated and symlinked.

## Why this matters

Symlinks let **every skill cross-reference real Odoo source code** instead of relying on training data. Any skill can read `base/sale/models/sale_order.py`, grep across `enterprise/`, diff between versions, or verify a dependency exists — all from the project directory.

## What is a "project"

One folder = one client = one Odoo version.

```
$PROJECTS_ROOT/EMPRESAX/           ← Project root. Run the skill from here.
├── CLAUDE.md                     ← Generated by this skill
├── base -> $ODOO_SRC/odoo18/addons        ← Symlink (dev only). Ojo: cada raíz nombra
├── enterprise -> $ODOO_ENTERPRISE_SRC/18  ← los majores distinto (odoo18 / 18 / v18).
├── OCA -> $OCA_SRC/v18                    ← Resuélvelo con `ls`: common:…/odoo-source.md
├── indaws-core -> ...            ← Symlink (dev only)
├── desarrollos/                  ← Custom modules
├── imports/                      ← Data files
└── docs/                         ← Analysis, minutes
```

- **cwd must be the project root** — never from inside `desarrollos/empresax_sale/`
- Symlinks point outward to shared source code
- Version change → new project folder or re-run this skill

See `references/shared/odoo-connection.md` for connection pattern and `references/shared/batch-limits.md` for pagination rules.

## Workflow

### Step 0 — Safety check
Verify cwd is a valid project root:
- `/`, `/tmp`, `~` → STOP: "Be inside your client's project folder"
- `__manifest__.py` in cwd → STOP: "You're inside a module, go up"
- Inside `$ODOO_SRC`, `$OCA_SRC`, `$ODOO_ENTERPRISE_SRC` → STOP: "You're in shared source code"
- CLAUDE.md already complete → re-run: show state, ask if user wants changes

### Step 1 — Role [STOP]
Ask: Developer or Consultant. Determines Steps 3/4 and skill options.

### Step 2 — Odoo Version [STOP]
Ask: 16.0, 17.0, 18.0, 19.0

### Step 3 — Source code setup (Developer only)
Clone/update repos, create symlinks, save paths to global config.
**Details:** See [workflow-developer.md](references/workflow-developer.md) + [git-repos.md](references/git-repos.md)

### Step 4 — Workspace structure (Consultant only)
Propose folder structure if project is empty/unorganized.
**Details:** See [workflow-consultant.md](references/workflow-consultant.md)

### Step 4.5 — Lint config detection (informational)

Detect presence of `.pre-commit-config.yaml`, `.editorconfig`, `pyproject.toml`, `eslint.config.cjs`, `prettier.config.cjs`, `.pylintrc`, `.pylintrc-mandatory`.

Report status in the final summary (Step 7). If any are missing **and** the role is developer, append a one-line hint suggesting `/git-migrate` to bootstrap. No `AskUserQuestion`. No delegation. No cross-suite dependency.

### Step 5 — Project needs [STOP]
MultiSelect skills based on role. See [skill-catalog.md](references/skill-catalog.md) for the full tables.

### Step 6 — Generate/Update CLAUDE.md
Create or update three **managed sections** (preserve all other content):

```markdown
## Odoo Version
{version}

## Skills recomendadas para este proyecto
- `/{skill-name}` — {brief description}

## Rutas locales
- `base/` → Odoo Community {version}
...
```

### Step 7 — Summary
```
Project: {dir}  |  Role: {role}  |  Odoo: {version}
Source: {N cloned, N updated, N skipped}
Symlinks: {N created, N skipped}
Skills: {list}  |  CLAUDE.md: {created|updated}
```

## Gotchas

1. **cwd is not a project** — Must run from client project root. Step 0 catches this.
2. **Inside a module** — `__manifest__.py` in cwd = wrong place.
3. **CLAUDE.md custom content** — Only touch the three managed sections. Everything else is sacred.
4. **Symlink to another version** — May be intentional. Ask before overwriting.
5. **Re-run** — If configured, show state and ask if user wants changes.
6. **Missing paths** — Not every dev has Enterprise or OCA. Skip and report.
7. **Consultant ≠ source code** — No clones, no symlinks. They use `odoo-pilot` and Studio.
8. **One project = one version** — Don't silently mix versions.
9. **SSH auth fails** — Private repos need SSH keys. Guide setup, don't just fail.
10. **OCA branch missing** — Some repos lack certain version branches. Script skips gracefully.
11. **Shallow clones** — `--depth 1` = no `git log`/`blame`. Intentional: we read source, not history.
12. **OCA timeouts** — 109 repos core; tardan. El script muestra `[N/109]` (total calculado del array).
13. **Never `git pull` blind on update** — a dirty working tree or a feature branch stomps work. **Fetch first** (behind counters are stale otherwise) and follow the SAFE decision table in [git-repos.md](references/git-repos.md) → *Update existing*: STOP+ask on dirty tree / branch ≠ target / diverged. OCA = N independent repos → offer "only project-used" vs "all"; never report "updated" if any repo was skipped.
