# inBuilt — Gotchas & Edge Cases

## Certification (IBG1-IBG15)

- **IBG1**: `billing_type` (origin/current) is **locked** once the first certification exists on a project. Cannot switch mid-project. _ES: No me deja cambiar el tipo de facturación (origen/actual) del proyecto una vez hecha la primera certificación._
- **IBG2**: Origin billing requires `certification_previous_billing_product_id` on the company. If missing → error on invoice creation. _ES: Al crear la factura de certificación por origen da error porque falta configurar el producto de facturación previa en la compañía._
- **IBG3**: Only **one draft** certification per project at a time. Must invoice or cancel before creating another. _ES: No puedo crear una nueva certificación porque ya hay otra en borrador; me obliga a facturar o cancelar la anterior._
- **IBG4**: Retention creates a **separate** `account.move` (`is_retention_move=True`). It's NOT a line on the main invoice — it's a second invoice document. _ES: La retención aparece como una factura aparte en lugar de una línea dentro de la factura principal._
- **IBG5**: Certification wizard propagates parent/child selection **bidirectionally**. Selecting a parent auto-selects all children. Deselecting all children auto-deselects parent. Uses `last_known_state` to prevent infinite loops. _ES: Al marcar un capítulo en el asistente de certificación se seleccionan solos todos sus subcapítulos y al desmarcarlos se quita el padre._
- **IBG6**: `certified_before_amount` aggregates ALL previous certifications (even cancelled ones if they had invoices). Check linked invoices, not certification state. _ES: El importe ya certificado anteriormente incluye certificaciones canceladas que llegaron a facturarse._
- **IBG7**: Invoice presentation `certified_lines` filters lines where `quantity_certified > 0`. Lines with 0 certified qty are silently excluded from the invoice. _ES: Las líneas con cantidad certificada a cero desaparecen de la factura de certificación sin avisar._
- **IBG8**: Certification lines inherit hierarchy from sale order lines via `section.line.mixin`. If the SO line hierarchy changes after certification lines are imported, the certification hierarchy does NOT update. _ES: Cambio el orden o la jerarquía de las líneas del presupuesto pero la certificación mantiene la estructura antigua._
- **IBG9**: `certified_percent` is computed from `quantity_certified / product_uom_qty`. If `product_uom_qty = 0` (section lines), percent is always 0 — this is expected. _ES: El porcentaje certificado de las líneas de capítulo o sección sale siempre a cero._
- **IBG10**: Cancelling a certification does NOT cancel its linked invoices. Must cancel invoices separately. _ES: Cancelo la certificación pero sus facturas siguen vivas; hay que anularlas por separado._

## Measurement (IBG11-IBG13)

- **IBG11**: When `sale.measurement` records exist on a SOL, `product_uom_qty` is computed from `sum(measurement.partial)`. Manual qty editing is blocked. Delete measurements to unlock. _ES: No me deja editar la cantidad de la línea de venta porque tiene mediciones; hay que borrarlas para desbloquearla._
- **IBG12**: `sale.measurement.partial = units × length × width × height`. If any dimension is 0, partial is 0. Common mistake: forgetting to set `units` (defaults to 0). _ES: La medición sale a cero porque olvidé rellenar las unidades o alguna dimensión quedó en cero._
- **IBG13**: `project.certification.measurement` is a **snapshot copy**, not a reference. Changing the original `sale.measurement` after certification does NOT update the certification measurement. _ES: Modifico la medición original después de certificar y la certificación no se actualiza._

## FIEBDC-3 Import (IBG14-IBG20)

- **IBG14**: FIEBDC3 job runs via **daily cron**. Jobs in `queued` state wait until next cron execution. For immediate processing, manually call `trigger_run()`. _ES: La importación del BC3 se queda en cola y no se procesa hasta el día siguiente._
- **IBG15**: `fiebdc3.percentage.map` uses `safe_eval` with a restricted context. Available variables: `code`, `bc3`, `siblings`, `base`, `material_base`, `stored_price`, `dr`, `di`. No access to `self.env` or ORM. _ES: En las fórmulas de porcentaje del BC3 no puedo acceder a env ni al ORM, solo a unas variables limitadas._
- **IBG16**: BC3 UOM mapping is done via `uom.uom` name matching. If a BC3 file uses a unit name not mapped in Odoo, the import creates a new UOM (which may cause duplicates). _ES: Al importar el BC3 se crean unidades de medida duplicadas porque el nombre no coincide con las existentes._
- **IBG17**: FIEBDC3 import creates products (`product.template`) if no match found by code. Default `type` = **`consu`** (Goods), from the wizard's `product_type` selection (`fiebdc3_import.py → product_type`, default `'consu'`); **only percentage (`%`) lines** are forced to `service` in `_prepare_product_vals`. So normal imported products are storable-track Goods, not services. _ES: Los productos importados del BC3 salen como bienes almacenables en vez de servicios._
- **IBG18**: Percentage map `code_pattern` uses exact match first, then wildcard. Pattern `%0*` matches any code starting with `%0`. Order matters: lower `sequence` wins. _ES: El mapeo de porcentajes coge un patrón que no esperaba; manda el de secuencia menor._
- **IBG19**: Failed jobs (`state='failed'`) can be manually retried by setting state back to `draft` then `queued`. Partial progress is NOT rolled back — may create duplicate lines if re-run. _ES: Reintento una importación fallida y me crea líneas duplicadas porque no se deshace el avance parcial._
- **IBG20**: FIEBDC3 chunked processing (100 lines) commits per chunk. If import fails mid-way, partial data exists in the SO. _ES: Falla la importación a mitad y el presupuesto queda con solo parte de las líneas cargadas._

## Margin & Cost (IBG21-IBG25)

- **IBG21**: `sale_indirect_purchase_price_percent` is company-level. All projects in the same company use the same indirect cost percentage. No per-project override. _ES: No puedo poner un porcentaje de coste indirecto distinto por proyecto; es único para toda la compañía._
- **IBG22**: Project margin computed fields (30+) use `@api.depends` chains that can be expensive on large projects. Avoid opening project form with 500+ SO lines — use list view. _ES: El formulario del proyecto tarda muchísimo o se cuelga con cientos de líneas de venta._
- **IBG23**: `project.cost.summary` aggregates from `account.analytic.line`. Timesheets that are NOT linked to a project task will NOT appear in the project cost summary. _ES: Los partes de horas que no están vinculados a una tarea no salen en el resumen de costes del proyecto._
- **IBG24**: Stock material costs on tasks come from `stock.move` valuation. If valuation method is `standard`, cost changes after delivery are NOT retroactively applied. _ES: Cambio el coste del material después de la entrega y el coste del proyecto no se actualiza._
- **IBG25**: `inbuilt_sale_margin_project` extends `project.project` with `sale_order_ids` (One2many). If a project has orders from multiple companies (inter-company), margin computation may include cross-company data unless filtered. _ES: El margen del proyecto mezcla datos de pedidos de otras compañías en escenarios intercompañía._

## Project Creation (IBG26-IBG28)

- **IBG26**: The project creation wizard (`inbuilt.project.create`) options `task_chapter` / `task_part` / `task_sub_parts` create tasks based on the **current** SO line hierarchy. Adding lines after project creation does NOT auto-create new tasks. _ES: Añado líneas al presupuesto después de crear el proyecto y no se generan tareas nuevas automáticamente._
- **IBG27**: `parent_sol_id` on `project.task` links to the sale order line that generated it. If the SOL is deleted, the task remains orphaned (no cascade delete). _ES: Borro una línea del pedido y su tarea queda huérfana sin eliminarse._
- **IBG28**: `inbuilt_sale_project` overrides `_compute_show_project_and_task_button()`. If another module also overrides this, there may be a conflict depending on MRO order. _ES: El botón de proyecto o tarea se comporta raro por un conflicto entre módulos que lo sobrescriben._

## Certification — Advanced (IBG29-IBG38)

- **IBG29**: Cancelling an **intermediate** certification (not the last) does **NOT** recompute `certified_before_amount` of subsequent certifications. The field's `@api.depends("project_id")` only triggers on project_id change, not on sibling state. **Silent desync risk.** Workaround: write any value to `project_id` on each subsequent certification to force a recompute. _ES: Cancelo una certificación intermedia y el importe certificado anterior de las siguientes no se recalcula, quedan descuadradas._
- **IBG30**: `project.certification._compute_state` treats **DRAFT** invoices as "invoiced" (filter: `state in ['draft','posted']`, not just 'posted'). A non-posted invoice already blocks edits on the certification. To re-edit: cancel or unlink the draft invoice first. _ES: No puedo editar la certificación aunque la factura solo esté en borrador; hay que cancelar o borrar esa factura primero._
- **IBG31**: Deleting a `sale.order.line` with `certification_line_ids` does NOT cascade. `sale_line_id` is Many2one without explicit `ondelete=`, so Odoo defaults to `set null`. Result: certification lines become orphans with broken `related` fields (name, code, quantity, etc.) and the next invoice regeneration excludes them. **No alert to user.** _ES: Al borrar una línea del pedido las líneas de certificación quedan rotas y desaparecen de la siguiente factura sin aviso._
- **IBG32**: `action_send_email` enters `mass_mail` mode for `len(self) > 1`, but does **NOT** preload `email_template_project_certification` in that mode. User must manually pick the template in the compose wizard for bulk sends. _ES: Al enviar certificaciones en bloque por email no se precarga la plantilla y hay que elegirla a mano._
- **IBG33**: `project.currency_id` and `sale.order.currency_id` can diverge. Certification uses `project_id.currency_id` for the invoice but reads SOL amounts in their native currency — **no explicit conversion**. If they differ, the invoice total is wrong. _ES: Si el proyecto y el pedido tienen monedas distintas, el total de la factura de certificación sale mal por falta de conversión._
- **IBG34**: Modifying a certification AFTER creating the invoice does NOT sync to the invoice (one-way build). Updates require: cancel invoice → reset certification to draft → regenerate. _ES: Modifico la certificación después de facturar y los cambios no se reflejan en la factura._
- **IBG35**: The `Add Lines` wizard rejects mixing SOs with different `fiscal_position_id`, `currency_id`, or `partner_invoice_id`. Validated in `_validate_order_consistency`. With `delete_existing_lines=False`, it also validates against pre-existing certification lines. _ES: El asistente de añadir líneas no deja mezclar pedidos con distinta posición fiscal, moneda o dirección de factura._
- **IBG36**: `certified_before_amount` aggregates **all non-cancelled** previous certifications, but a draft invoice already counts as "invoiced" (IBG30) — sometimes a draft certification with no invoice still affects `before` calculations because `last_certification_line_id` filters by `state in ['draft','cancel']` differently than `_compute_state`. _ES: Los cálculos de certificado anterior descuadran porque una certificación en borrador sin factura influye en el importe._
- **IBG37**: `quantity_certified` lower bound is `quantity_certified_before` — but `before` reads from `sale_order_line.last_certification_line_id`, which excludes draft and cancel. If you cancel the previous certification, the floor drops, allowing the next to certify a value lower than what was historically invoiced. _ES: Al cancelar la certificación anterior puedo certificar una cantidad menor que la ya facturada históricamente._
- **IBG38**: `_check_billing_type_not_change_if_certifications_exist` constraint counts **cancelled** certifications too. Once any certification exists (even cancelled), `billing_type` is locked forever on the project. _ES: El tipo de facturación queda bloqueado para siempre aunque la única certificación existente esté cancelada._

## FIEBDC-3 — Advanced (IBG39-IBG48)

- **IBG39**: BC3 re-import on an existing SO does **merge by code** (`code`, `parent_code`, `fiebdc3_path`). Lines in the SO not present in the new BC3 stay untouched (**orphan lines from old import**). On matched lines, `cost_ids` and `measurement_ids` are **fully replaced** with `Command.clear()` + creates. _ES: Al reimportar el BC3 quedan líneas viejas que ya no están en el archivo, y en las coincidentes se reemplazan costes y mediciones._
- **IBG40**: Wizard rejects re-import if the previous `fiebdc3_job_id` is in state other than `done`/`failed`/`False`. Check is on latest job state, not BD lock — a tiny race window exists when two users click Import simultaneously. _ES: No deja reimportar si el trabajo anterior no terminó; si dos usuarios importan a la vez hay riesgo de choque._
- **IBG41**: Auto-created percentage parsers (`_auto_create_percentage_parsers`) skip codes whose parser exists with `active=False`. A previously **disabled** parser causes silent ignore of all matching `%`/`&` codes in subsequent imports — no warning. _ES: Un parser de porcentajes desactivado hace que se ignoren en silencio todos los códigos de porcentaje en las siguientes importaciones._
- **IBG42**: FIEBDC3 cron uses `_trigger()` (event-driven), not interval. The daily schedule is fallback only. If the cron is `active=False`, `_trigger()` does nothing and jobs stay `queued` indefinitely. **No watchdog.** Workaround: re-queue via the **Queue** button in `fiebdc3.job` form or call `model.trigger_run()` from a server action. _ES: Los trabajos de importación se quedan encolados indefinidamente si el cron está desactivado, sin ningún aviso._
- **IBG43**: Ephemeral products (`product.template` with `fiebdc3_sale_id`) and BC3-mapped UoMs (`uom.uom.fiebdc3_code`) are created **without** `company_id`. In multi-company they are globally visible. Code reuse by `default_code` across companies can cross-contaminate. _ES: Los productos y unidades creados por la importación BC3 son visibles en todas las compañías y se contaminan entre ellas._
- **IBG44**: When the import reuses an ephemeral product from a PREVIOUS SO (by `default_code` match), the product's `fiebdc3_sale_id` still points to the first SO. Deleting that first SO cascades the product deletion (`ondelete='cascade'`), breaking the second SO's references. _ES: Borro el primer pedido y desaparece un producto que reutilizaba otro pedido, rompiendo sus referencias._
- **IBG45**: Auto-created UoMs all fall in `uom_categ_unit` (Unit category) with `factor=1.0`. A BC3 file mixing `m3`, `kg`, `h` produces UoMs that **cannot convert between each other**. Manually pre-map UoMs to correct categories before importing. _ES: Las unidades creadas al importar (m3, kg, h) no se pueden convertir entre sí porque quedan todas en la misma categoría._
- **IBG46**: `recalculate_price_from_cost=True` does `price_unit = sum(c.so_price)` without currency conversion. If `so_price` is in a different currency than the SOL, the result is silently wrong. _ES: Al recalcular el precio desde el coste, si los costes están en otra moneda el precio de venta sale mal sin avisar._
- **IBG47**: FIEBDC3 job commits per chunk (default 100 lines, configurable via `ir.config_parameter` `inbuilt_fiebdc3_import.quotation_chunk_size`). On failure mid-import, processed chunks remain persisted (no transaction rollback). Code includes an explicit comment: *"Deliberate transaction commits — refactor to a job-queue pattern is out of scope."* _ES: Si la importación BC3 falla a mitad, los bloques ya procesados se quedan guardados sin poder deshacerse._
- **IBG48**: `%` parsers in `split` mode (`{'mode':'split'}`) require **Product Unit of Measure** and **Product Price** decimal precision = 4 (Settings → Technical → Decimal Accuracy). With default 2 decimals, small yields round to zero and lines disappear silently. README warns explicitly. _ES: Con precisión decimal a 2, las líneas de porcentaje pequeñas se redondean a cero y desaparecen; hay que subir la precisión a 4._

## Project Creation — Advanced (IBG49-IBG55)

- **IBG49**: The wizard updates tasks **in-place** via `sale.order.line.task_id`. Re-running on a SOL with `task_id=False` creates a new task without unlinking any pre-existing one matched by name/code. Manual `task_id` unlinks cause silent duplicates. _ES: Al reejecutar la creación de proyecto se crean tareas duplicadas si toqué a mano el vínculo entre tarea y línea._
- **IBG50**: Asymmetric write in `_save_task`: **task name** is recomputed and updated on every re-run (`[code] name` from current SOL), but **task description** is only written on CREATE. Manually edited descriptions survive re-runs, manually edited names get overwritten. _ES: Al reejecutar el asistente se sobrescribe el nombre de la tarea que edité a mano, pero la descripción se conserva._
- **IBG51**: `allocated_hours` is recomputed on each wizard run from `cost_ids.is_time` recursively. Manual time adjustments on the task get overwritten. Manual `allocated_hours` cannot be preserved. _ES: Las horas asignadas de la tarea se sobrescriben en cada reejecución y no puedo mantener un ajuste manual._
- **IBG52**: Mixing `chapter_subtasks=True` and `chapter_subtasks=False` across re-runs on the same project can leave parent-chapter tasks with duplicated or doubled hours. The wizard does not reconcile when toggling the option mid-flow. _ES: Al cambiar la opción de subtareas por capítulo entre ejecuciones, las tareas de capítulo quedan con horas duplicadas._
- **IBG53**: Cancelling a `sale.order` does NOT propagate to its `project.project`. The project stays active with `sale_order_ids` pointing to a cancelled SO. Cleanup is manual. _ES: Cancelo el pedido de venta y el proyecto sigue activo apuntando a un pedido cancelado._
- **IBG54**: Moving a SOL between chapters (changing `parent_id`) IS reflected in the task hierarchy on re-run. But **deleting** a SOL leaves the task orphaned (no cascade, see IBG27). _ES: Mover una línea entre capítulos sí actualiza la tarea al reejecutar, pero borrarla deja la tarea huérfana._
- **IBG55**: `inbuilt_sale_project.action_create_project` falls back to `super()` (Odoo standard) when `order_type_id.create_project=False`. If the standard flow is triggered (e.g., service with tracking), the inBuilt wizard is bypassed — tasks may be created with different logic. _ES: En ciertos casos, como servicio con seguimiento, se salta el asistente inBuilt y las tareas se crean con otra lógica._

## Stock & MRP — Advanced (IBG56-IBG62)

- **IBG56**: Missing `dest_location_id` or `default_stock_route_id` on a project triggers `UserError` **per-partida** while processing, not as a pre-flight check. Some partidas may persist before another fails. Configure both fields before opening the project. _ES: Da error al procesar cada partida por falta de ubicación destino o ruta; algunas partidas ya se guardaron antes del fallo._
- **IBG57**: When the manufacture path creates a `mrp.bom`, it **overwrites** any pre-existing BoM matched by `(product_tmpl_id, type='normal')` via `Command.clear()` on `bom_line_ids`. Hand-configured BoMs are silently replaced. The module does NOT tag inBuilt-created BoMs. _ES: La creación de proyecto reemplaza en silencio una lista de materiales que había configurado a mano._
- **IBG58**: Phantom BoMs (`type='phantom'`) unlink ALL `stock.warehouse.orderpoint` records for the product (incompatible per Odoo). The deletion is **destructive and not logged**. Removing the phantom BoM later does NOT restore the orderpoints. _ES: Al usar lista de materiales fantasma se borran las reglas de reabastecimiento del producto sin registro ni forma de recuperarlas._
- **IBG59**: A partida with `manufacture` route AND `cost_ids` of category `is_material`: the material costs go into the BoM as components, and `project.stock.move` for them is suppressed (`inbuilt_sale_project_mrp_stock_material/_create_or_update_task_material_from_cost` returns empty). The SOL's main product still creates one stock move. _ES: Los materiales de una partida de fabricación van a la lista de materiales y no generan movimientos de stock propios._
- **IBG60**: Re-running `Create Project` after removing a `cost_id` from a SOL leaves an orphan `project.stock.move` pointing to the deleted `sale_cost_id`. The wizard matches by `(project_id, sale_cost_id)` and never unlinks stale moves. _ES: Quito un coste de una línea y al reejecutar queda un movimiento de stock huérfano apuntando al coste borrado._
- **IBG61**: A SOL with `product_type='service'` AND `manufacture` route triggers `_create_boms`, which creates a `mrp.bom` with `product_tmpl_id` of a service product. MRP normally rejects service products in BoM at runtime — error appears only on MO confirmation. _ES: Una línea de servicio con ruta de fabricación crea una lista de materiales que solo falla al confirmar la orden de fabricación._
- **IBG62**: Service-type SOL children of a manufacture partida are excluded from BoM components (`_get_mrp_components_from_sale_children` filters `type != "service"`), but a service SOL **as the main partida** still creates the BoM. Asymmetric filter. _ES: Un servicio hijo se excluye de los componentes, pero un servicio como partida principal sí crea la lista de materiales._

## Measurement & Certification Snapshot (IBG63-IBG66)

- **IBG63**: Adding `sale.measurement` records to a SOL **after** creating its certification line does NOT propagate. `project.certification.measurement` are created only in the `create` of `project.certification.line` (one-shot copy). The SOL gets `sol_has_measurements=True` (which blocks manual edits) but the new measurements have no certification counterpart — the certifiable quantity falls short with no way to fix it. _ES: Añado mediciones a la línea después de crear la certificación y no se propagan; la cantidad certificable se queda corta sin arreglo._
- **IBG64**: Editing dimensions on a `sale.measurement` that is already partially certified recalculates `partial` (related, store=True), but does NOT revalidate `quantity_certified` of `project.certification.measurement`. Possible to end up with `quantity_certified > partial` (the inverse validation only fires on direct write). **Latent integrity bug.** _ES: Edito dimensiones de una medición ya certificada y la cantidad certificada puede quedar mayor que la medición real._
- **IBG65**: `sale.measurement` deletion cascades to `project.certification.measurement` (`ondelete='cascade'`) WITHOUT protection — even when the certification is posted/invoiced. The invoice stays intact but the audit trail is lost. **No protection for certified measurements.** _ES: Borro una medición y desaparece su certificación asociada aunque esté facturada, perdiendo la trazabilidad._
- **IBG66**: `project.certification.measurement` does **NOT** declare an `ir.rule` for multi-company filtering. `company_id` is `related="certification_line_id.company_id", store=True` but record rules are not inherited from related fields. Possible cross-company read leak. _ES: Posible fuga de datos entre compañías porque las mediciones de certificación no filtran por compañía._

## Budget vs Real Margin (IBG67-IBG72)

- **IBG67**: Budget vs Real is a **one-way comparison**: real costs (from `account.analytic.line`) NEVER update budgeted costs (in `sale.order.line.cost`). The pestaña Summary is a dashboard, not a sync mechanism. To reflect a real cost in the budget, edit the SOL manually (needs `indaws_sale_order_line_edit`). _ES: Los costes reales nunca actualizan el presupuesto; el resumen es solo informativo, hay que editar la línea a mano._
- **IBG68**: `project.sale_cost_summary_ids` and `project.project_cost_summary_ids` are computed `store=False` — fresh on each read, but recomputation creates/writes/unlinks physical records in `sale.order.cost.summary` / `project.cost.summary` per read. Heavy on large projects opened concurrently. _ES: Abrir el resumen de costes en proyectos grandes va muy lento porque recalcula y reescribe registros en cada lectura._
- **IBG69**: Multi-currency in `sale_cost_summary`: subtotals from different SOs are summed **raw**, without converting to project currency. SOs in EUR + SOs in USD on the same project produce arithmetic sums treated as the project's currency. **Latent bug.** _ES: En un proyecto con pedidos en EUR y USD los subtotales se suman sin convertir, dando cifras erróneas._
- **IBG70**: `_process_analytic_vendor_bill` uses `abs(amount)`. A **credit note** (factura rectificativa) of a supplier is recorded with positive value, not negative. Refunds do NOT subtract from real cost in the project summary. _ES: Una factura rectificativa de proveedor no resta del coste real del proyecto; se suma como si fuera positiva._
- **IBG71**: Cost summary at task level includes only analytic lines with `task_id=this`. Cost summary at project level includes ALL analytic lines for the project's `account_id` (with and without task). **No deduplication**: totals at project level overlap with task-level rollups. _ES: Los totales de coste a nivel de proyecto solapan con los de tarea y se cuentan dos veces._
- **IBG72**: A timesheet whose `analytic_account_id` differs from the project's `account_id` is **silently invisible** in the project's real-cost summary. Filter is exact-match. Configuration error in analytic distribution causes hidden costs. _ES: Un parte de horas con cuenta analítica distinta a la del proyecto no aparece en el coste real y queda oculto._

## Retention — Lifecycle (IBG73-IBG75)

- **IBG73**: `indaws_account_retention` automates **creation** of the retention `account.move` on `_post`, cancellation on factura cancel, and unlink on factura delete. There is **NO** automatic **release/return** flow for handing the retained amount back to the customer at project completion. Manual reverse journal entry is required. _ES: No existe un flujo automático para devolver la retención al cliente al terminar la obra; hay que hacer el asiento manual._
- **IBG74**: Modifying `retention_percent` on a posted invoice updates the field but does **NOT** recreate the retention move if it is also posted. The check is `if not move.retention_move_id` — already-existing posted retention moves are kept stale. To fix: button_draft on the invoice (cancels the retention move), edit %, re-post. _ES: Cambio el porcentaje de retención en una factura ya validada y el asiento de retención sigue con el importe antiguo._
- **IBG75**: `project.certification.retention_percent` propagates to `account.move.retention_percent` only at invoice creation. Subsequent edits to the certification's retention percent never reach the already-created invoice. _ES: Cambiar el porcentaje de retención en la certificación no llega a la factura ya creada._

## Sale Order — Compute Side Effects (IBG76-IBG77)

- **IBG76**: `inbuilt_sale_measurement._compute_product_uom_qty` forces `qty = sum(measurement.partial)` when measurements exist. Manual edits to `product_uom_qty` get reverted on the next recompute trigger. To break the link, delete the measurements first. _ES: La cantidad editada a mano en la línea de venta se revierte porque hay mediciones que la fuerzan._
- **IBG77**: `sale_cost_summary_ids` aggregates from SOs in any state except `cancel` — **DRAFT presupuestos are already included**, inflating `sale_amount_total` and budget figures before confirmation. Filter is by `state != 'cancel'`, not `state in ('sale','done')`. _ES: Los presupuestos en borrador ya suman en los totales de venta y coste, inflando las cifras antes de confirmar._
