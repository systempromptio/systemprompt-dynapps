El rol del consultor en la era de la IA

De "hacer" a "decidir y comunicar"
El rol del consultor con la IA cambia: ya no tiene que ejecutar cada tarea, tiene que tomar decisiones y comunicar con el cliente. La ejecución es de la IA, pero las decisiones —la parte clave del éxito— son responsabilidad humana.
La comunicación es el centro de todo
La interacción con el cliente pasa a ser el punto fundamental del trabajo. Llamamos, comunicamos, nos acercamos al cliente. El toque humano es clave para el éxito de cualquier proyecto.
Confianza y tranquilidad
El consultor es la figura experta que da confianza y tranquilidad al cliente. Con dominio de las herramientas y la metodología, transmitimos seguridad en cada fase del proyecto.
A tiempo y dentro del presupuesto
El objetivo sigue siendo que los proyectos salgan a tiempo y dentro del presupuesto. El control del alcance es parte clave del éxito. Cada paso de este documento es de obligatorio cumplimiento.
Simplicidad siempre
Simplicidad es siempre clave del éxito: ajustarnos lo máximo a la base de Odoo. No improvisamos, seguimos las reglas marcadas y usamos las herramientas de las que disponemos.
Trabajo en equipo y control total
Trabajamos como equipo, con control completo del proyecto en todo momento. La IA es nuestra aliada, pero el liderazgo y la responsabilidad son nuestros.
Para alcanzar la excelencia, es necesario que toda persona en Indaws siga al pie de la letra esta guía de trabajo.
La consistencia en la metodología es lo que nos diferencia. No hay atajos: seguimos el proceso, usamos las herramientas y entregamos calidad.

Skills orientados a la captación y cualificación de leads, preparación de demos y propuestas comerciales. 5 skills del repositorio sales.

lead-data-collection

v1.3 sales

Prepara un formulario de toma de datos pre-rellenado para llamadas de descubrimiento con leads de implantación Odoo. Extrae datos del crm.lead (descripción, chatter últimos 50 mensajes, adjuntos, tags, etapa) y del contacto (sector, web, número de empleados) via odoo-pilot, y analiza la web del cliente via WebFetch. Pre-rellena un formulario de 7 secciones (~55 preguntas clave) indicando la fuente de cada dato ([PRE-RELLENADO - web/adjunto/chatter/oportunidad]). Los campos sin información se marcan como [PREGUNTAR] en naranja. Detecta 12 módulos basándose exclusivamente en señales (ningún módulo se incluye por defecto). El formulario HTML se guarda en x_studio_ai_toma_de_datos del lead.

Entrada: ID o nombre del crm.lead + credenciales Odoo corporativo
Salida: Formulario HTML pre-rellenado en x_studio_ai_toma_de_datos + nota interna en chatter
Ejemplo: "Prepara la toma de datos para la oportunidad 42" → Lee el CRM y la web del cliente, genera formulario con módulos detectados ([PRE-RELLENADO]) y preguntas pendientes ([PREGUNTAR] en naranja). Incluye guía de factores multiplicadores de horas.

demo-script-generator

v1.0 sales

Genera un guión interno de demo personalizado para el consultor y una agenda profesional HTML para compartir con el cliente, a partir de los datos de una oportunidad CRM. Lee el crm.lead (descripción, tags, chatter, x_studio_ai_toma_de_datos, adjuntos ir.attachment) via odoo-pilot — la revisión de adjuntos es obligatoria ya que frecuentemente contienen las necesidades reales del cliente con mayor detalle. Analiza pain points del cliente y mapea a flujos de demo de 10 apps Odoo aplicando el framework F.A.V.O.R.I.T.E. con estructura temporal adaptable a 30/60/90 minutos. Máximo 5 flujos para evitar feature overload. Complementa a demo-builder: este skill genera el guión, demo-builder genera los datos.

Formaciones

La formación correcta determina si el cliente puede operar de forma independiente tras el go-live. La calidad de una implantación se mide por lo poco que el cliente necesita llamarnos después. Skill: training-planner

Planificación inicial: Al inicio del proyecto se ejecuta training-planner para planificar a alto nivel todas las formaciones del proyecto.
Antes de cada formación: Se ejecuta de nuevo training-planner para esa formación concreta, generando los materiales específicos.
Tras la reunión de formación: Ejecutar project-meeting-minutes. Este skill genera el acta de la reunión pero también detecta acciones decididas y verifica si caen dentro del alcance, proponiendo acciones si hay desvíos.
Regla 50/50: 50% teoría (flujos, reglas de negocio) + 50% práctica (ejercicios con datos reales del cliente).
Regla de los 20 minutos: Máximo 20 minutos de teoría sin interacción del usuario. Después, ejercicio práctico obligatorio.
Scope por invocación: training-planner genera materiales para UNA formación concreta
3 entregables por formación: plan de formación + guía de sesión + cheat sheet
Datos reales del cliente, nunca de demo — los errores de flujo aparecen con datos reales
Formación después de configuración: el sistema debe estar configurado antes de impartirla

Peticiones al Cliente (x_client_request)

Sistema para gestionar peticiones formales al cliente: datos, documentos, decisiones, accesos y validaciones. Usa mail.thread para comunicación vía chatter, con cotejo inteligente que evita duplicados y descarta lo que ya está en el análisis. Skill: client-request-manager

GENERAR
Analiza tarea + análisis funcional. Crea requests en draft. Descarta lo que ya está en el análisis.

Al inicio del proyecto se lanza en modo GENERAR para crear las peticiones iniciales. En este caso analiza todas las tareas del proyecto, no solo una en concreto.
FOLLOW-UP
Dashboard del proyecto. Envío de emails validados. Recordatorios con intensidad según días de retraso. Detección de respuestas.
CERRAR
Marca como recibidas las requests respondidas. Modo bulk para múltiples peticiones a la vez.
5 Tipos de petición con deadline típico:
information — Información necesaria para configurar (7 días)
data_file — Fichero Excel/CSV para importar (14 días)
validation — Validación de lo implementado (7 días)
decision — Decisión del cliente sobre alternativas (5 días)
access — Accesos a sistemas externos (7 días)
Cotejo inteligente: Si la información ya está en el análisis funcional, la petición se descarta automáticamente — se muestra al usuario con referencia a la sección exacta del análisis.
Nunca: mencionar información interna (horas, health scores, términos técnicos) en emails al cliente.

Modelo de Datos en Odoo

Adaptaciones de Odoo corporativo para la gestión de proyectos de implantación. Campos Studio y modelos personalizados.

1 Descripción de adaptaciones

Indaws ha personalizado su instancia de Odoo mediante campos Studio y modelos custom para gestionar de forma integral los proyectos de implantación. Estas adaptaciones permiten vincular proyectos con artículos Knowledge, gestionar checklists ponderados por tarea, controlar peticiones al cliente con estados y deadlines, y generar informes de seguimiento con health score automático. Todos los skills del ecosistema interactúan con estos modelos a través de odoo-pilot (API XML-RPC).
