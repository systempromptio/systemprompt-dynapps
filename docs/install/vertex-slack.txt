*Vertex AI credentials for the Astound gateway*

We are replacing the local Python proxy with our gateway. The gateway keeps credentials in a secret store and reads each one once at boot, so we need two credentials from Google Cloud project `enterprise-ai-505512`.

*1. `vertex` — a Vertex AI API key (Gemini 2.5 Pro / Flash / Flash-Lite)*
• Endpoint we call: `https://aiplatform.googleapis.com/v1beta1/publishers/google/models/{model}:generateContent`
• The key is sent on the `x-goog-api-key` header (express mode). No service account, no OAuth exchange.
• Please issue a Vertex AI API key restricted to the Vertex AI API and send us the key string.
• Please check it before sending:
```
curl -sS -H "x-goog-api-key: $KEY" -H 'content-type: application/json' \
  https://aiplatform.googleapis.com/v1beta1/publishers/google/models/gemini-2.5-flash-lite:generateContent \
  -d '{"contents":[{"role":"user","parts":[{"text":"ping"}]}]}'
```

*2. `vertex_maas` — the open models (Qwen3, GLM-5, Kimi K2, DeepSeek V3.2, GPT-OSS)*
• Endpoint we call: `https://aiplatform.googleapis.com/v1beta1/projects/enterprise-ai-505512/locations/global/endpoints/openapi/chat/completions`
• This endpoint authenticates with a Google OAuth 2.0 access token on `Authorization: Bearer`, not an API key. The old proxy minted one per request from Application Default Credentials. An access token expires after one hour, so a pasted token is not a working credential.

What we need, in order of preference:
1. *A service-account JSON key* with `roles/aiplatform.user` on the project. The gateway will exchange it for access tokens and refresh them itself. This is the option we are building for.
2. *Confirmation that a Vertex AI API key works on this endpoint.* If API-key access is enabled for Model Garden partner models, the same kind of key as above works and no service account is needed. Test it with:
```
curl -sS -H "x-goog-api-key: $KEY" -H 'content-type: application/json' \
  https://aiplatform.googleapis.com/v1beta1/projects/enterprise-ai-505512/locations/global/endpoints/openapi/chat/completions \
  -d '{"model":"openai/gpt-oss-20b-maas","messages":[{"role":"user","content":"ping"}]}'
```
A `200` means option 2 is open. A `401` mentioning an OAuth token means we need option 1.

*Models the credential must be entitled to* (each must be enabled in Model Garden for the project; a model that is not enabled returns 404 to every user who picks it):

*How developers reach them*
Nothing changes on the developer's machine. The bridge install points Claude Code at the gateway and turns on model discovery, so every model above appears in Claude Code's `/model` picker beside the Claude models as soon as the credentials are in place. Every call is recorded with the user, tokens and cost in the same audit trail as our Anthropic traffic.
