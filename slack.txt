*Correction on the Google Drive connector — no seats needed*

Yesterday's list assumed Gemini Enterprise licences were a prerequisite. They are not, and I've now proven it: in a GCP project of my own with nothing but the Discovery Engine API enabled, I created the federated Google Drive data store and an Enterprise-tier search app, and its MCP server (`https://discoveryengine.googleapis.com/mcp`) answers `search` for my signed-in account. The product is *Agent Search* (Discovery Engine, ex-Vertex AI Search). Gemini Enterprise is the licensed end-user app that sits on the same engine — it is not part of this connector, and nobody needs a seat to search from Claude Code. Usage-billed, 10k queries/month free.

The connector and its skill are on `next` today: `google_drive` (Agent Search over Drive, Gmail, Calendar and the directory, live, filtered to what each user can already open — their Drive permissions, their own mailbox and calendar). I've dropped the RAG Engine connector — with per-user Drive ACLs available live there is no reason to hold a corpus copy; Vladimir's corpora remain usable from the console for the project that built them.

*What changes in the ask*
• *Drop:* A1 (licences + seats), A2 (Gemini Enterprise identity-provider settings), A7's "with seats". The per-seat price question for Terry goes away.
• *Keep:* A3 — now four federated data stores (Drive, Gmail, Calendar, People) with one search app over all of them (an app created on one store can't gain a second later; I can script all of it against the API if you give my account `roles/discoveryengine.admin` on the project), A4 the engine name, A6 IAM for the pilot group — `roles/discoveryengine.viewer` (or a custom role with `discoveryengine.servingConfigs.search`) + `roles/mcp.toolUser`, audit logs on.
• *Add:* enable `discoveryengine.googleapis.com` on the project, and in Workspace Admin → API controls → Manage app access mark the Google-owned Agent Search client as Trusted — without it Drive search returns zero results (Google says up to 24 h to propagate). Users need both smart-features toggles on in Gmail → Settings → General ("Smart features and personalization", both toggles).
• *A5 is now exact:* the scope is `https://www.googleapis.com/auth/discoveryengine.readwrite` (from the endpoint's own protected-resource metadata), not `cloud-platform`.
• B and C are unchanged, except that the acceptance test (two users, one file) can be done by any two Workspace users — no seats.
